# Documentation

Documentation is part of the product. Keep it accurate, clear, useful, and version-aware.

## When to create or update

Prefer documenting:

- Architectural decisions
- Non-obvious behavior
- Configuration
- Trade-offs
- Operational requirements
- External integrations

Update documentation when behavior, structure, or contracts change.

## Avoid redundant documentation

Do not duplicate information that already lives in a clearer canonical source.

Prefer short, actionable docs over exhaustive narration.

## External references

When documenting third-party tools or systems:

- Prefer official sources
- Distinguish tool, protocol, framework, architecture, technique, platform, and methodology
- Include version or last verification date when the information may change
