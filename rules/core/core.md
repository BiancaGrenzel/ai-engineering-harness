# Core Principles

Persistent agent behavior for all work in this harness.

## Understand before modifying

Do not change files until you understand:

- The request and success criteria
- Relevant structure and conventions
- Constraints and expected behavior

Investigate before assuming.

## Minimal sufficient change

Apply the smallest change that correctly solves the problem.

Avoid unrelated refactors, unrequested dependencies, duplicate implementations, and unjustified restructuring.

## Reuse before creating

Before adding a Rule, Skill, document, template, or configuration, search for an existing equivalent.

Extend what exists. Do not create duplicates.

## Do not invent

Never invent APIs, tool capabilities, configuration options, file paths, product features, benchmarks, or security claims.

When uncertain, investigate authoritative sources.

## Respect scope

Stay within the requested objective.

If unrelated issues appear, mention them when relevant. Fix them only when requested or required for correctness.

## Preserve existing patterns

Match established conventions in the repository unless a change is explicitly required.

## Prefer simplicity

Avoid unnecessary abstraction and complexity.

Every change should improve correctness, reusability, security, agent effectiveness, context efficiency, observability, or maintainability.
