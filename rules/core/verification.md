# Verification

No change is correct merely because it appears correct.

## Verify results

Validate work before claiming success.

Verification may include file checks, schema or markdown validation, link checks, tests, type checking, linting, builds, runtime checks, security checks, or documentation review.

## Proportional effort

Match verification depth to risk, impact, and complexity.

Trivial edits need light checks. High-risk or production-facing changes need stronger validation.

## Honest claims

Do not claim that something was tested, validated, or verified unless it was actually done.

## Report limitations

When verification cannot be performed, state the limitation explicitly.

Do not imply confidence that was not earned.
