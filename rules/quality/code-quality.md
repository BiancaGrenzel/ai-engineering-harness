# Code Quality

Prefer code that is easy to understand, change, and verify.

## Clarity and simplicity

Write clear, direct implementations.

Avoid cleverness that increases cognitive load without proportional benefit.

## Maintainability

Prefer designs that are easy to modify safely.

Keep coupling low. Keep responsibilities focused.

## Consistency

Follow existing project conventions for naming, structure, and style unless a change is explicitly required.

## Avoid premature abstraction

Do not introduce abstractions, frameworks, or indirection until a concrete need is demonstrated.

Reuse existing patterns before inventing new ones.

## Language and framework neutrality

These quality principles apply across languages and stacks. Do not assume a specific toolchain.
