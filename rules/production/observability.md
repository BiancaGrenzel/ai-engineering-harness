# Observability

Observability should make system behavior inspectable in production.

## Signals

Consider:

- Logs
- Metrics
- Traces
- Errors
- Latency
- Cost
- Model usage

Choose the signals that answer real operational questions for the system.

## Questions to answer

Observability should help answer:

- What happened?
- Why did it happen?
- How expensive was it?
- How long did it take?

## Practical constraints

Prefer actionable signals over volume.

Avoid logging secrets or unnecessary sensitive data.

Do not assume a specific observability vendor.
